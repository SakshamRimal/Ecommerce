# Database & Migrations

## When to use

- Adding a table/column/index/enum.
- Changing relationships or cascades.
- Writing or reviewing an Alembic revision.
- Working with pgvector embeddings.
- Debugging schema/model mismatches.

## Files

| Concern | File |
|---|---|
| Declarative base + mixins | `src/app/db/base.py` |
| Engine + session factory | `src/app/db/session.py` |
| Models | `src/app/models/*.py` |
| Model exports | `src/app/models/__init__.py` |
| Alembic config | `alembic.ini` |
| Alembic env | `src/migrations/env.py` |
| Revisions | `src/migrations/versions/*.py` |

## Conventions

- Base mixins: `UUIDPrimaryKeyMixin` (UUID PK) and `TimestampMixin`
  (`created_at`, `updated_at`, timezone-aware UTC).
- Tables use plural snake_case names.
- FKs use explicit `ondelete` (`CASCADE` for owned children, `RESTRICT` for
  referenced catalog rows).
- Money uses `Numeric(10, 2)`.
- Embeddings use `pgvector.sqlalchemy.VECTOR(1536)`.
- JSONB is not used yet.

## Schema

| Table | Key columns | Relations |
|---|---|---|
| `users` | email unique, hashed_password, full_name, is_active, role enum | 1→N carts, chat sessions |
| `categories` | name unique, slug unique | 1→N products |
| `products` | name, description, price, stock_quantity, category_id FK, version, embedding vector(1536) | N→1 category, 1→N cart_items |
| `carts` | user_id FK | 1→N cart_items |
| `cart_items` | cart_id, product_id, quantity; unique(cart_id, product_id) | N→1 cart/product |
| `orders` | user_id FK, status enum, total_amount, idempotency_key unique | 1→N order_items |
| `order_items` | order_id, product_id, product_name, unit_price, quantity | N→1 order |
| `chat_sessions` | user_id FK | 1→N chat_messages |
| `chat_messages` | session_id, role enum, content | N→1 session |

## Migration workflow

```bash
# after editing models
uv run alembic revision --autogenerate -m "describe change"
# review the generated file, then
uv run alembic upgrade head
# rollback one
uv run alembic downgrade -1
```

`env.py` imports every model so autogenerate sees the full metadata.

## Rules

1. Review autogenerated migrations — Alembic misses enum/index details.
2. Never edit an applied migration; add a new revision.
3. Every migration needs a working `downgrade()`.
4. Use `server_default` when adding NOT NULL columns to populated tables.
5. Keep model `Enum` names compatible with the DB enum names.
6. Create pgvector indexes explicitly (`ivfflat`/`hnsw`).

## Gotchas

- SQLAlchemy stores enum **names** (`CUSTOMER`, `ADMIN`) while the Python enum
  **values** are lowercase (`customer`, `admin`). The API emits values, so be
  careful when writing raw SQL.
- `products.version` migration uses `server_default=0` but the model default is
  `1`.
- The embedding ivfflat index is created with `lists = 100`; it needs enough rows
  to be useful and should be `ANALYZE`d after bulk loads.
- `main.py` auto-upgrades using `/app/alembic.ini` (Docker only).
- Database URL is built with `postgresql+asyncpg://`; tools that need sync
  drivers must convert it.

## Verify

```bash
uv run alembic current
uv run alembic upgrade head
uv run alembic downgrade -1 && uv run alembic upgrade head
```
